# Live acceptance (Herdr-managed pane only)

Run in disposable Git repositories **inside Herdr** with real, locally available Claude/OpenCode/Codex model credentials. Automated unit tests do not validate live session behavior. Never run live pane/agent/worktree commands from an external terminal or use production task worktrees for destructive tests.

1. Run `herdr-flow doctor`. Configure private worker/reviewer exact model IDs; leave the shipped default coordinator as unpinned Claude. From Claude, `/ai-plan <small reversible request>` and verify `brief.md`, a decision-ready handoff, one worker, one independent reviewer, and final review in the **same Claude session**. For `--plan-only`, verify implementation does not start.
2. In the private config, set a Codex coordinator model/effort. From OpenCode `/ai-plan <request>` and Codex `$herdr-flow-plan <request>` (or `/prompts:ai-plan` after restarting Codex), verify **one task per request**, complete brief transfer, pinned coordinator session, distinct worker pane, and final review in the original coordinator session. Repeat with an OpenCode coordinator default. Revert the private default afterward; existing tasks must retain the coordinator selection frozen in their state.
3. Produce an independent FAIL and confirm repair goes to the same worker (or a selected separate fixer). Repeat review; verify strict PASS/FAIL evidence, final-review FAIL → repair → review → final review, and optional escalation after the configured cumulative failure threshold. No task should auto-commit or auto-merge.
4. Start tasks in two different projects with the same task ID; confirm agent names, registries, state, panes and prompts never cross projects. Send overlapping completion commands and settled events; verify at most one prompt/session for the next phase.
5. Trigger blocked, missing, and uncertain-prompt conditions in disposable tasks. Do not bypass a blocked agent, replace a live coordinator, or automatically resend an uncertain prompt. `inspect` first; recover only when the recorded session is genuinely absent.
6. In a project with ignored root `AGENTS.md` and `CLAUDE.md`, verify snapshots and `.herdr-flow-context.md` are worktree-local, and no `.env` or ignored settings are copied. Confirm Docker/Compose commands are not run against shared/main-checkout services blindly. Change the source instructions; status should report drift and future handoffs should wait. From Herdr, explicitly refresh only after inspection and agents becoming idle. Modified worktree copies must never be overwritten.
7. Verify new branches use inferred conventional type/slug names (`Optimize ...` → `refactor/optimize-...`), `--branch-type` overrides inference, and duplicate names receive task IDs only when needed. Rename a disposable task branch with `git branch -m`: `finalize` should verify the exact Git reflog rename and preserve it in task history; ambiguous renames must stop with the explicit `reconcile-branch --branch <actual> --yes` recovery path. Verify `finalize` refuses unmerged branches, dirty worktrees, extra ignored files, user-edited snapshots, foreign panes, and busy task agents. After a human commits and performs a real ancestry-preserving merge, `finalize` should remove only the clean task worktree/workspace, preserving the branch and `.ai/workflow` records.

If a gate fails, stop and record the task ID, phase, state file, panes, and error; do not retry an uncertain send or discard work.
