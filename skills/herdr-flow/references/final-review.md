# Herdr Flow final release gate

The original coordinator independently reviews the current task worktree after independent review PASS. Read `handoff.md`, `brief.md` if present, `implementation.md`, `review.md`, `decisions.md`, the actual diff, and applicable worktree instructions. Verify every requirement, acceptance criterion, Definition of Done item, prior reviewer finding and regression/security/performance/memory risk. Re-run practical validation; do not trust unverified implementation claims. Mark any critical unverified check explicitly and FAIL if it prevents commit/merge readiness. Record concrete evidence, remaining gaps and an explicit release decision in `final-review.md`, with `## Status` exactly PASS or FAIL. Do not fix the implementation yourself, merge, commit, reset, or delete branches/worktrees. Run `herdr-flow final-result --task <task-id> --status PASS|FAIL` after writing the report. On FAIL the controller routes repairs through the configured persistent repair session and another independent review.
