# Herdr Flow coordinator planning contract

This contract applies identically to Claude, OpenCode, and Codex coordinators. The initiating agent may be a launcher rather than the coordinator; do not implement the task from the launcher.

1. Read `state.json`, `brief.md` (the original user request), `handoff.md`, `.herdr-flow-context.md` in the task worktree, and applicable project `AGENTS.md`/`CLAUDE.md` instructions. Check whether commands from the main checkout actually work in this isolated worktree; never blindly run Docker commands against shared services or the main checkout.
2. Investigate the existing architecture, relevant code paths, dependencies, conventions, existing utilities, current behavior, and root cause. Clearly distinguish observed facts from assumptions and recommendations. Do not change production files or configuration; planning only.
3. Ask the user in this persistent coordinator session about material ambiguity before deciding. Never guess authorization for an irreversible or high-stakes choice. Do not launch implementation while questions remain open.
4. Replace `handoff.md` placeholders with objective and background, requirements, observable acceptance criteria, a specific implementation strategy and affected files, reuse opportunities, constraints, edge cases, backward compatibility, risks (including performance, memory/OOM, security and concurrency), relevant validation commands, and a clear Definition of Done. Do not include credentials or `.env` contents. Record decisions in `decisions.md`.
5. Before starting, inspect `herdr-flow status --task <task-id>` and ensure the handoff is complete. If `state.json` sets `planning.auto_start` to `false`, stop and report the task ID, handoff location and how to start later; leave automation off. Otherwise run `herdr-flow run --task <task-id>` **once from this coordinator's Herdr pane**. The controller starts the worker and handles later review/repair gates; never ask the user to launch every phase.
6. When the controller returns the final-review prompt, use `references/final-review.md` in this skill as the evidence gate, write `final-review.md` and run `herdr-flow final-result --task <task-id> --status PASS|FAIL` once. Never commit, merge, remove a worktree, reset or discard unrelated work.
7. If a session is blocked, missing, or prompt delivery is uncertain, inspect `herdr-flow status` and `herdr-flow inspect --role coordinator` as appropriate; never launch another coordinator or blindly resend a prompt.
